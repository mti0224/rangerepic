# 玩家前端（2026-09-26）

玩家流程：首頁 → 角色與職業 → 選擇角色 → 選擇職業／查看效果 → 編組隊伍 → 對戰。

## 角色顯示條件

正式來源為 `data/game/characters/*.json` 與 `data/game/classes/*.json`。只有同時符合下列條件的職業會出現在玩家端：

- `characterId` 對應到已建立的角色。
- `assetVariantId` 對應到已核准的圖資，且可讀取動畫設定。
- 該職業存在於 Gameplay 目錄。

沒有職業的角色不顯示。圖資本身不再自動變成相容職業。目錄載入失敗會顯示錯誤與重試按鈕，不會回退到舊角色清單。目前資料只有熊大的 `brown_test`（終極黑衣熊大）；新增其他角色職業後，符合條件即自動出現。

## 職業與隊伍

- 同一角色的職業會集中在一個角色入口；職業數量沒有硬編碼。
- 職業詳情顯示 HP、攻擊力、爆擊機率、爆擊傷害、命中率，以及普通攻擊、普通輔助、技能、能力。
- 職業選擇以 `rangerepic:classes:v1` 儲存。每次進入該角色優先顯示上次選擇的職業。
- 隊伍以 class ID 儲存；同一隊最多五位角色，同一角色的不同職業不能重複出場，對手可使用相同角色。
- 首次載入會將 `lr:formation` 內能對應到正式職業的舊圖資 ID 遷移，移除無職業角色、重複角色與舊候補欄位。角色目錄載入失敗時不覆寫存檔。
- 首頁職業頁確認後，已在隊伍內的同角色會切換職業；空隊伍仍需由編組頁指定位置。

## 已移除的原型頁面

移除舊首頁的示範好友、示範貨幣／體力、佔位功能，以及舊抽卡、通行證、商店／背包、裝備升級、故事地圖與結算、舊英雄頁、舊隊伍預設頁。玩家端不再載入原型角色的官方技能／數值描述。戰鬥資訊改用正式職業名稱與數值，隱藏舊星級、屬性類型、DEF 與 SPD。

圖資管理、角色數據管理及後台 API 保留。舊存檔中的背包／通行證等內容不主動刪除；仍被舊引擎或測試引用的相容模組也保留，避免破壞管理與戰鬥工具。

## 位置與驗證

- `src/play/playerRoster.ts`：可用職業清單、角色分組、隊伍遷移與放置規則。
- `src/play/ClassSelection.tsx`：角色／職業頁與新規格詳情。
- `src/play/TeamBuilder.tsx`：雙方隊伍編組。
- `src/play/PlayMode.tsx`：載入、存檔、頁面與戰鬥串接。
- `src/play/player.css`：響應式玩家介面。

`npm run test:player-roster` 驗證清單篩選、共用圖資的不同職業、舊存檔遷移、重複限制與空目錄；`npm run test:gameplay-v1` 驗證既有戰鬥規則。部署流程同時編譯管理後台及玩家前端。
